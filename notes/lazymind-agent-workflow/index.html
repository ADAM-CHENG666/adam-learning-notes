宿主差异 · 会话控制与面板渲染

CDP 如何接入宿主窗口

CDP（Chrome DevTools Protocol）是 Chromium 的调试协议。Codex 和 WorkBuddy 的 Host Connector 共用 CdpClient，通过 Runtime.evaluate 在对应宿主窗口里执行 JavaScript。这样接入代码能调用宿主的会话接口，也能把面板挂到聊天界面。 CDP 官方文档

宿主反向会话控制面板挂载
Codex

CodexAdapter 经 CodexNative 和 CDP 按 thread ID 找到原聊天，开启回合或中断属于这次工作流的回合。

宿主明确拒绝且允许重试时，重发前会用 HostBridge.action() 复查通知。执行中断前也会复查。

 经 CDP 将面板挂到聊天界面，用 Codex 原生浏览器 WebView 打开 Assistant Bridge 的本机包装页。
WorkBuddy WorkBuddyAdapter 经 CDP 调用会话 SDK。按会话 ID 找到原聊天，用 sendPrompt() 唤醒，用 cancel() 中断该会话的当前回合。 经 CDP 找到对应的聊天内容区并挂载 iframe，加载 Assistant Bridge 的本机包装页。
DSH

插件里的 dshRuntime 直接用 SDK 的 SessionController 定位会话、排入消息或取消。Coordinator 接入回合和工具事件。

reconcile() 可查宿主持久事件，核对之前的消息是否已送达。

 插件注册 conversation.input.dock 槽位，用 iframe 直接打开 LazyMind 嵌入页。

Codex 和 WorkBuddy 共用展示循环来选择要显示的 run，各自用 UIAdapter.syncPanel() 挂载容器。三个宿主最终都加载 /workflow-runs/:sessionId/embed，由 LazyMind Web 的 WorkflowPanel 和 SlotRenderer 渲染标签页和产物。
