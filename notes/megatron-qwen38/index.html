Megatron 新模型接入

框架分工与构网概念

verl
编排采样、训练和权重同步。
Megatron Core
运行训练模型，提供并行与调度。
Megatron Bridge
适配 HF 模型的构网和权重转换。
vLLM

Qwen3.8 接入是在 Bridge 中注册模型家族适配器，复用既有的 Megatron Core 和并行调度。

1. 把 HF 模型接入 Megatron 展开 ＋收起 −

这一章交付一个从 HF checkpoint 初始化、能在目标并行配置下正确更新参数的 Megatron 模型。更新后的权重是下一章在线同步的输入。

子任务 1　确定模型规格和训练范围

做什么

从 HF 配置、权重索引和参考实现核实规格，再确定本轮启用哪些部分和更新哪些权重。

目的
明确后续要搭哪张网、装哪些权重，以及以什么配置和输入做对照。
验收指标
来源和参考版本可追溯，配置与实际张量的形状和 dtype 对得上。每项预期权重和 buffer 都有加载、训练、冻结或排除规则。记录目标并行、资源预算和对照输入。

子任务 2　实现模型适配

做什么

AutoBridge 识别 HF 模型并选择对应的 Bridge 实现。

目的
在目标并行布局下构建 HF 定义的模型，并把权重装到各 rank 的对应位置。
验收指标
  • 网络架构　标准入口构建出的层数、模块、调用顺序和状态接口符合模型定义。
  • 参数映射　完整加载权重和 buffer，独立核对各 rank 的值。BF16 纯重排的 HF → Megatron → HF 往返逐项一致。
  • 并行支持　各 rank 的层、张量和专家归属符合配置，跨组状态的形状和数据类型符合接口约定。

子任务 3　接通训练并验证参数更新

做什么
把训练 batch 的 token、position、mask 和 label 接到模型，配置 loss、反向与优化器。正式 verl 路径还要处理 packing 的样本隔离、变长微批和 loss 归一化。
目的
让模型在正确的 token 上算出 loss，并使梯度更新到预期的参数。
验收指标
  • 前向　固定同一权重和输入 token，与参考实现的 logits、逐 token logprob 按冻结阈值对照。
  • Loss　用同一份 logits 独立复算，核对下一 token 标签偏移、mask 和有效 token 数。
  • 参数更新　在目标训练入口和并行配置跑真实 optimizer.step()。梯度有限，指定参数实际变化，冻结参数和静态 buffer 保持原值。

Qwen3.8 实测

11 月 17–19 日的接入记录。Leader 先确定调试范围和对照，再实现模型适配，最后把验证从四层扩大到完整模型。

  1. 确定模型规格和本轮训练范围

    实际工作　核对 Qwen3.8-Flash-Next BF16 的配置、索引和 131 个分片头。首轮选纯文本、关闭 MTP，取前四层做调试，冻结 PLE 表和 QSA indexer。前四层涵盖 3 层 GDN、1 层 QSA、HC 和 PLE，每层保留全部 512 个专家。团队缩小 PLE 表，保留查表和注入路径。441 个保留张量与源权重的 SHA-256 一致。

    环境问题　共享 vLLM 环境用 Python 3.11，Bridge 需要 3.12，两端的 Transformers 版本要求也没有交集。Leader 固定了两套各自独立的 Python 3.12 环境，保持相同 Ray 版本，先用小张量验证跨环境的 verl CUDA IPC 传输。

    对照问题　Leader 要求本轮独立建立 vLLM 冷启动基线。原生 QSA 在长输入触发选择性选块后出现重复运行波动。团队试过确定性 top-k，随后按 leader 的要求撤回补丁，改用原生结果冻结验收规则，6 类选择性 QSA 输出保留未决。

  2. 实现 Qwen3.8 的 Bridge 适配

    网络架构实现　在 Bridge 中新增 Qwen38Model 和 DecoderLayer，复用 Core 的 GDN、MoE，接入 Qwen 的 HC、PLE 和 QSA。HC 和 PLE 先各自验证前后向，再经 AutoBridge 组装四层网络。

    参数映射　用 98 组规则处理专家编号、投影拆合和 PLE 分片。四层单卡的 114 个 HF 文本状态键对应 4,222 项 Megatron 逻辑状态，独立核对加载值，两次完整导出逐项一致。

    并行支持　四层实测 EP、PP、TP 及 EP2+PP2 组合。PP2 把四层分成两段，沿用 Core 调度，在两段间传递四路 HC 残差。

    调试问题和四层 PP 图

    模块复用　Core mHC 使用流级门控，Qwen 用低秩网络生成逐特征门控。团队复用归一化等基础设施，保留 Qwen 的公式。PLE 参考 DeepSeek Engram 和 Gemma 的实现，保留自身的哈希、门控和卷积。

    GDN 反向　梯度核对发现 TE 反向会重读模块权重。团队改为以单位缩放调用 TE 归一化，再按 Qwen 原顺序应用可训练的缩放参数，复跑前后向。

    导出入口　verl 缓存转换任务时，AutoBridge 分派的新 Bridge 实例缺少先前构建阶段的配置。修复后从实际模型恢复映射所需配置，再验证缓存入口和 CUDA 导出。PLE 表也按行拼接，并核对 padding 和三个整数 buffer。

  3. 验证计算和参数更新，再扩大到 48 层

    同一个 Megatron 先算稳　四层固定输入重复运行时，MoE 专家输出的 BF16 原子累加顺序会引入波动。Leader 启用 Core 已有的 TE 汇总路径，三个独立进程各跑三轮，输出逐位一致。

    四层做真实更新　用固定的小批次跑前向、反向和一次独立 SGD。590 项参数实际变化，冻结项和静态 buffer 保持原值。

    48 层定位训推差异　用同一权重和 token 比 Megatron 与 vLLM。首轮短样本的最大 logprob 差为 2.6882。逐层回放发现，第 1 层 HC 的舍入顺序先引入差异，GDN 中间精度继续带来偏差，第 3 层 MoE 在路由边界换了一个专家，放大了输出差。给两边相同的 MoE 输入时，路由 logits 和专家集合都一致。跨实现 BF16 前向仍超出门槛。

    Loss 与正式训练　48 层分片交叉熵与用同一份 logits 复算的 FP32 参考最大差为 1.91e-6，通过该用例的 loss 计算检查。正式训练审查仍有 packed sequence 样本隔离和变长微批的 loss 归一化待补验，完整模型的优化器更新也待验收。

2. 把训练权重同步给 vLLM 展开 ＋收起 −

这一章把 Megatron 当前持有的权重交给已经在运行的 vLLM。一次同步要走完 Bridge 导出 → verl 传输 → vLLM 加载 → 发布版本，下一轮采样使用完整的新版本。

子任务 1　从训练侧导出目标版本的权重

做什么
Bridge 用 export_hf_weights() 读取 Megatron 内存里的参数。按训练侧 TP/PP/EP 布局重组分片，产出 HF 名称和布局的张量流，同时明确冻结参数与 buffer 的处理规则。
目的
把同一个版本的模型状态转换成 vLLM 能按名称理解的张量。训练和推理可以采用各自的并行布局。
验收指标
所有必要 rank 参与导出。按目标版本的独立清单核对名称、shape、dtype、专家编号和内容，覆盖冻结权重与必要 buffer。纯 BF16 布局变换按位核对。

子任务 2　用 verl 把张量交给推理 worker

做什么
verl 将多个张量装进可复用的通信缓冲区。Qwen3.8 的同机实验通过 CUDA IPC 传递显存句柄及名称、形状、dtype 和字节偏移。超过桶容量的单个源张量使用独立句柄直传。
目的
小张量合批以减少进程间交接次数，大张量直传以控制额外暂存显存。
验收指标
逐项对比发送和接收的元数据及内容散列。接收端消费完一桶再确认，发送端收到确认后才复用缓冲区。覆盖漏桶、重复项、错误内容、中断超时及大张量直传。

子任务 3　由 vLLM 写入运行中的模型

做什么
运行在 vLLM worker 内的 verl 扩展接收张量，调用 vLLM 的 load_weights()。loader 按推理侧分片写入目标参数，处理跨桶到达的融合参数和必要 buffer，整轮接收后完成加载后处理。
目的
让 vLLM 每个 rank 最终持有该版本的正确分片，包含融合后的完整权重和推理所需状态。
验收指标
核对 loader 实际写入集合。用同一权重和推理配置独立冷启动 vLLM，逐 rank 比较最终参数、持久 buffer、分片和别名。FP8 路径还要独立验证 scale、重打包及重复换权。

子任务 4　安全发布版本并恢复采样

做什么
换权前暂停采样，处理在途请求。协调器汇总整轮张量清单、loader 结果和所有 worker 回执，使旧的 KV 和前缀等缓存失效，发布新版本后再放行。失败时保持暂停，用一次新的全量同步恢复。
目的
vLLM 会逐桶写入，换权期间显存中可能暂时同时存在新旧数据。统一放行让一次 rollout 只使用一个已验证的完整版本。
验收指标
失败事务即使已写入首桶也无法发布或产出样本。成功后首个新请求的旧缓存命中为 0。重复同步、版本切换和回退都与对应冷启动参考一致，样本可追溯到实际权重版本。

用两组实验验证整条链路

零步 θ₀
用初始权重做在线同步。隔离的测试引擎先扰动部分权重和 buffer，再检查是否恢复到独立冷加载的 θ₀。这能验证转换、传输和加载确实执行了。
训练后 θ₁
在 Megatron 做真实参数更新。让已运行的 vLLM 从 θ₀ 热更新到 θ₁，用独立冷加载的同一份 θ₁ 核对状态和固定 token 输出，并检查实际变化。

Qwen3.8 实测

11 月 18–19 日的记录。Leader 先用四层 BF16 验权重搬运，再做真实更新和故障注入，最后把零步试验扩大到完整 48 层。

  1. 先导出 θ₀，再为 θ₁ 建独立参考

    实际工作　四层模型的 Bridge 从 Megatron 导出了 114 个 HF 命名 CUDA 张量，逐项对照初始 checkpoint。做完真实 SGD 后，同一入口从训练进程的内存导出 θ₁。

    怎么核对新版本　实验另存了 θ₁ 快照，用独立映射从快照重建 4,222 项训练端状态，再与 Megatron 的实际状态逐项核对。另一个 vLLM 进程独立冷加载这份 θ₁，给热更新提供对照。

  2. 用真实 IPC 传输，检查桶和 worker 的边界

    首次试验的问题　接收观测器挂在了错误位置，虽然权重恢复了，接收明细仍是空的。团队把观测移到真正执行接收和加载的 vLLM worker，再完整重跑。512 MiB 配置下，114 个张量共形成 15 个接收批次。

    复测怎么做　同版本连续用 512、64、2048、512 MiB 同步。64 MiB 时，第一层 GDN 的 QKV 和 Z 分别进入两个桶，loader 最终把它们写进同一份融合权重。每层 3200 MiB 的专家 gate/up 张量单独走 IPC 直传。四轮张量内容一致，确认了缓冲区复用和跨桶融合。

  3. 扰动后恢复，再验真实更新是否写入

    零步　四层测试引擎实际扰动了 89 项可写状态，涵盖全部专家及 PLE 整数 buffer。同步后，连同静态 scale 共 93 项状态与冷加载逐位一致。只留一个专家未恢复的对照也能被检出。

    训练后　θ₁ 热更新后的 93 项状态与 θ₁ 冷加载逐位一致，其中 75 项相对 θ₀ 确实改变。16 项可判定输出检查全过，最大 logprob 差为 0。6 类选择性 QSA 的输出因原生重复性波动仍未决，真实更新整项保持待验收。

  4. 让不完整版本无法发布，并实测全量恢复

    遇到的问题　vLLM 0.32 的暂停接口与旧调用不兼容。团队按实际接口派发并让失败向上传播。初次故障注入还发现漏桶、缺 LM head、截短专家矩阵和同形状错切片会被误报成功。

    怎么修和怎么验　把预期张量清单、连续桶序号、封存内容散列和整轮回执接进 verl。四层 GPU 试验中，七类故障均被拒绝。即使首桶已写入，推理仍保持暂停。全量重发 θ₁ 后，93 项状态逐位匹配冷端，恢复后的首个请求旧缓存命中为 0。封存前的切片正确性仍由第一章的独立映射核对覆盖。

    完整模型已验　48 层 BF16 在 Megatron TP2+PP2+EP2 到 vLLM TP4 的布局上实测了零步换权。训练端重组 1,294 个源张量，每个 vLLM worker 的 962 项状态匹配独立冷加载，短输入回放一致。

    待验收　选择性 QSA 长输入的输出仍未决。正式 verl 作业的多副本恢复已有 CPU 回归，GPU 在线换权仍待验收。完整模型训练后的换权和 FP8 rollout 也待验收。

3. 联调连续 RL

工程工作
在正式 verl 作业里，用真实 rollout 的奖励计算 Advantage，再用 RL loss 驱动 Megatron 更新。同步新权重后开始下一轮采样。
验收指标
连续运行多个 step。逐轮核对奖励进入训练、参数实际变化、下一批样本使用的权重版本，并记录 reward、loss 和换权开销。
Qwen3.8 实测
已有训练端加载与优化器初始化记录。完整模型的优化器更新和正式 verl 连续 RL 仍待验收。
